# 架构模式

## 分层架构

```
┌─────────────────────┐
│    表现层           │  UI 组件、API 路由
├─────────────────────┤
│    应用层           │  用例编排、业务流程
├─────────────────────┤
│    领域层           │  业务逻辑、实体
├─────────────────────┤
│    基础设施层       │  数据库、缓存、外部服务
└─────────────────────┘
```

- **依赖方向：** 外层依赖内层，内层不知道外层的存在。
- **接口隔离：** 每层暴露最小契约，实现细节隐藏。

## 模块结构

```
src/
  modules/
    users/
      index.ts          # 公共 API
      entity.ts         # 领域模型
      service.ts        # 业务逻辑
      repository.ts     # 接口（端口）
      http-handler.ts   # 表现层（适配器）
      db-repository.ts  # 基础设施层（具体实现）
  shared/               # 横切关注点
    errors/
    utils/
    types/
```

- **模块按功能划分，不按技术层划分。**
- 每个模块拥有自己的实体、服务和接口。
- `shared/` 仅在被 2+ 模块共用时才放公共代码。

## 依赖管理

- **依赖注入优于单例。** 通过构造函数传递依赖。
- **端口与适配器模式。** 接口定义契约，实现放在基础设施层。
- **禁止循环依赖。** 由构建工具强制执行。检测到循环时，将共享类型提取到 `shared/types/`。

```typescript
// 端口（领域层的接口）
export interface UserRepository {
  findById(id: string): Promise<User | null>;
}

// 适配器（基础设施层的实现）
class DbUserRepository implements UserRepository { ... }

// 在组合根目录注入
const service = new UserService(new DbUserRepository());
```

## 设计规则

- **组合优于继承。** 使用接口和依赖注入，而非深层类层次。
- **边界开放失败，内部关闭失败。** API 返回 4xx/5xx，内部代码抛类型化错误。
- **配置即数据。** 环境配置是纯对象，非硬编码。启动时校验。
- **幂等操作。** 所有变更操作（API 调用、DB 写入）必须安全可重试。

## 反模式

| 反模式 | 问题 | 修复 |
|--------|------|------|
| 服务层直连数据库 | 绕过仓储抽象 | 添加仓储接口 |
| 共享工具包 | 循环依赖、上帝模块 | 就近放置到使用方 |
| 单例服务 | 难测试、隐藏依赖 | 构造函数注入 |
| 深层继承链 | 脆弱、难修改 | 组合 + 接口 |
| 表现层使用 ORM | 数据层泄漏到 UI | 仓储模式 |
